# **أنواع أنظمة الـ Version Control**

## 1️ **Local Version Control System (LVCS)**

**ده أبسط نوع**. كل حاجة بتحصل **على جهازك بس**.

### 📌 فكرته:

- تكون عامل فولدر على جهازك.
    
- كل نسخة من المشروع بتتحفظ **محليًا**.
    
- مفيش سيرفر ولا مشاركة مع حد.
    

### ✔ المميزات:

- سهل جدًا ومفيهوش تعقيد.
    
- مفيش إنترنت → مفيش مشكلة.
    

### ✘ العيوب:

- **مش مناسب لأي فريق**.
    
- لو جهازك باز → كل الشغل راح.
    
- صعب تتبع التعديلات بشكل احترافي.
    

### 📌 مثال:

- أدوات زي: RCS (الأديم جدًا).
    

---

## 2️ **Centralized Version Control System (CVCS)**

**فيه سيرفر مركزي** بيخزن النسخة الرئيسية من المشروع.

### 📌 فكرته:

- كل المطورين يتصلوا بسيرفر واحد.
    
- يسحبوا منه النسخة.
    
- يعملوا تغييراتهم.
    
- يرفعوها تاني على نفس السيرفر.
    

### ✔ المميزات:

- مناسب للشغل الجماعي.
    
- easy to manage.
    
- كل الملفات في مكان واحد.
    

### ✘ العيوب:

- **لو السيرفر وقع → كل الفريق يقف**.
    
- لازم إنترنت.
    
- السيرفر نقطة فشل واحدة (Single Point of Failure).
    

### 📌 مثال:

- SVN
    
- Perforce
    
- CVS
    

---

## 3️ **Distributed Version Control System (DVCS)**

وده الأحدث والأقوى، زي **Git**.

### 📌 فكرته:

- كل فرد في الفريق عنده **نسخة كاملة من الريبو** (History + كل حاجة).
    
- مش محتاج سيرفر علشان تشتغل.
    
- السيرفر مجرد مكان للتنسيق، مش المتحكم.
    

### ✔ المميزات:

- **أسرع بكتير** لأن أغلب العمليات محليًا.
    
- مفيش نقطة فشل واحدة.
    
- تقدر تعمل branches بسهولة.
    
- تقدر تشتغل offline تمامًا.
    

### ✘ العيوب:

- محتاج مساحة أكبر لأن كل واحد عنده نسخة كاملة.
    
- في البداية ممكن يكون أصعب من الـ Centralized.
    

### 📌 مثال:

- Git (الأشهر)
    
- Mercurial
    

---

# مقارنة سريعة

| النوع       | أين تُحفظ النسخ؟  | مناسب لفريق؟ | يحتاج إنترنت؟ | أمثلة |
| ----------- | ----------------- | ------------ | ------------- | ----- |
| Local       | جهاز المستخدم فقط | ❌ لا         | لا            | RCS   |
| Central     | سيرفر مركزي واحد  | ✔ نعم        | ✔ غالبًا      | SVN   |
| Distributed | كل جهاز عنده نسخة | ✔ نعم        | ❌ لا (محليًا) | Git   |



# **Download vs Clone**

## 1) **Download**

لما تعمل **Download** من GitHub أو أي منصة تانية:

### 💡 يعني إيه؟

- بتاخد **الملفات بس** زي ما هي في اللحظة الحالية.
    
- **مفيش history**.
    
- **مفيش branches**.
    
- **مفيش Git tracking**.
    
- ده زي إنك بتنزل فولدر عادي من النت.
    

### 📌 استخدامه:

- لما تكون عايز تشوف المشروع أو تجرب الكود **من غير ما تشتغل على Git**.
    

### 👎 العيب:

- مش هتقدر تعمل commit
    
- ولا تتابع التعديلات
    
- ولا تبوش تغييراتك
    
- ولا تشتغل كشريك في المشروع
    

---

## 2) **Clone**

لما تعمل `git clone` فده غير تمامًا 👇

### 💡 يعني إيه؟

- بتنزل **كل ملفات المشروع** + **كل الـ Git history**:
    
    - كل الـ commits
        
    - كل الـ branches
        
    - كل الـ tags
        
    - كل الـ logs
        
- وبيتعامل جهازك مع الريبو كأنه نسخة محلية كاملة من المشروع.
    

### ✔ المميزات:

- تقدر تعمل commit وتخزن تعديلاتك.
    
- تقدر تعمل branches.
    
- تقدر تبوش للتغييرات (لو معاك صلاحيات).
    
- بتشتغل كأنك جزء من الفريق فعلاً.
    

---

# الفرق في جملة واحدة:

- **Download = نسخة ملفات فقط**
    
- **Clone = نسخة المشروع + تاريخ كامل + Git tools**
    

---

# مثال بسيط شبه الحياة:

تخيل عندك كتاب:

📥 **Download**  
= نسخة PDF من آخر طبعة فقط.

📥 **Clone**  
= نسخة PDF + كل المسودات القديمة + ملاحظات المؤلف + كل الإصدارات السابقة.
